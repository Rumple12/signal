# Obid Labs — Instructions for Codex

Scope: all files under `labbs/obid/` for DT081A Signal and Image Processing, Labs 1–3.

## Before editing

1. Read `labbs/obid/REPORT_WRITING_STYLE.md` in full, and apply it to every new or revised report passage, caption, table explanation, and code-snippet explanation.
2. Read the teacher's exact question and starter example for the section being worked on.
3. Read Obid's existing report text for the same lab. Treat the approved Lab 1 Section 1.1 PDF as the reference for tone, answer length, and Q&A formatting.
4. Work on the section named in the user's current prompt only. Do not change approved sections, other students' work, code, figures, values, or layouts without an explicit reason and authorization.

## Non-negotiable rules

- Write Obid's report in **simple, natural university-student English**, not formal research prose.
- Use the teacher's question as a labeled question, followed by **Answer:** and a short, direct response supported by Obid's real experiment results.
- No generic introductions, filler, excessive jargon, needless disclaimers, or unsupported claims.
- Accurate mathematics, units, terminology, data, and figure references always take priority over style.
- Create results from Obid's own work. Do not copy, lightly rewrite, recolor, or republish another student's report or generated figures.
- Keep the teacher's fixed experiment settings where specified; use independent inputs/settings only where the task allows them.
- Report a missing measurement or unsupported observation rather than inventing it.
- Preserve the teacher's report structure: Introduction; Experimental Setup; Results and Analysis; Discussion; Conclusion; selected code snippets when useful.
- Figures should be clear and correctly labeled. Do not add unnecessary experiments or visualizations.
- Build and visually inspect the changed PDF. Verify all five (or the actual number of) teacher questions in scope and check that existing approved content remains unchanged.
- Do not commit or push unless the current user prompt explicitly asks for it.

## At the end of every task

Briefly report: section/questions covered, files changed, values or figures checked, PDF build/visual status, and any remaining problem. Say when something could not be verified.
